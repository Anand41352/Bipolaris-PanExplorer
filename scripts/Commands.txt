5. Repeat identification and masking

A hybrid approach was used, combining homology-based repeat masking and de novo repeat discovery.

5.1 Homology-based repeat masking

Software: RepeatMasker v4.1.9
Repeat database: Dfam v3.9
Repeat category: Fungi
Output format: GFF
Parallel processes per genome: 4

Command for one genome

mkdir -p repeatmasker_results/STRAIN_NAME

RepeatMasker \
  -species fungi \
  -pa 4 \
  -gff \
  -dir repeatmasker_results/STRAIN_NAME \
  STRAIN_NAME.genome.fasta

Command for all 19 genomes

mkdir -p repeatmasker_results

for genome in *.genome.fasta
do
    strain=$(basename "$genome" .genome.fasta)

    mkdir -p "repeatmasker_results/$strain"

    RepeatMasker \
        -species fungi \
        -pa 4 \
        -gff \
        -dir "repeatmasker_results/$strain" \
        "$genome"
done

Parameters:
- -species fungi: Uses the fungal repeat library.
- -pa 4: Uses four parallel processes per genome.
- -gff: Generates GFF annotation output.
- -dir: Specifies the output directory.
- *.genome.fasta: Processes all genome FASTA files matching this naming pattern.

Note: The loop above processes genomes one after another, with four parallel processes within each RepeatMasker run. It does not run all 19 genomes simultaneously.

5.2 De novo repeat library construction using RepeatModeler

Software: RepeatModeler v2.0.7
Purpose: Identify novel and strain-specific repetitive elements and construct genome-specific repeat libraries.
Threads: 20

Activate the environment:
conda activate repeatmodeler_env

Step 1: Build the RepeatModeler database
BuildDatabase \
  -name STRAIN_NAME \
  STRAIN_NAME.genome.fasta

Step 2: Identify repetitive elements
RepeatModeler \
  -database STRAIN_NAME \
  -threads 20

Parameters:
- -name: Name assigned to the RepeatModeler database.
- STRAIN_NAME.genome.fasta: Input genome FASTA.
- -database: RepeatModeler database generated by BuildDatabase.
- -threads 20: Uses 20 CPU threads.
Output: A genome-specific repeat library, generally named:
consensi.fa.classified

Rename it for the corresponding strain:
cp RM_*/consensi.fa.classified STRAIN_NAME_custom_lib.fa

Run this procedure separately for each strain, keeping its database and output files in a separate directory.
5.3 Second-round RepeatMasker using custom repeat libraries
The custom libraries generated by RepeatModeler were used for a second round of masking.

Software: RepeatMasker v4.1.9
Library: Strain-specific RepeatModeler library
Engine: RMBlast
Parallel processes: 16
Command
mkdir -p repeatmasker_denovo/STRAIN_NAME

RepeatMasker \
  -lib STRAIN_NAME_custom_lib.fa \
  -engine rmblast \
  -pa 16 \
  -gff \
  -dir repeatmasker_denovo/STRAIN_NAME \
  repeatmasker_results/STRAIN_NAME/STRAIN_NAME.genome.fasta.masked

Parameters:
- -lib: Custom repeat library generated by RepeatModeler.
- -engine rmblast: Uses RMBlast as the search engine.
- -pa 16: Uses 16 parallel processes.
- -gff: Generates GFF annotation output.
- -dir: Specifies the output directory.
- Input FASTA: Homology-based masked genome from the first RepeatMasker run.
Important: Check the actual output filename from your first RepeatMasker run before using it as the second-round input. RepeatMasker normally appends .masked to the input filename.




6. Gene prediction and annotation

Gene prediction and annotation were performed using MAKER v3.1.4, integrating transcriptomic evidence, protein homology evidence and *ab initio* gene prediction.

## 6.1 Transcriptome data preparation

A total of 14 RNA-seq datasets were used: 12 datasets from the *B. sorokiniana* D2 strain and two datasets from the LK93 strain.

### A. D2 transcriptome data

The propiconazole/azole-stressed *B. sorokiniana* transcriptome dataset was obtained from NCBI SRA under BioProject **PRJNA417354**.

Study: Transcriptome sequencing of azole-stressed *Bipolaris sorokiniana*.

NCBI BioProject: `PRJNA417354`

The D2 transcriptome datasets were subjected to quality control, adapter trimming and transcriptome assembly.

### B. LK93 transcriptome data

Two RNA-seq datasets corresponding to wild-type mycelia of *B. sorokiniana* LK93 were retrieved from NCBI SRA.

BioProject accession supplied for these datasets: `PRJNA743515`

SRA run accessions:

```bash
prefetch SRR15044366
prefetch SRR15044367
```

Convert SRA files into FASTQ format:

```bash
fasterq-dump SRR15044366 --split-files
fasterq-dump SRR15044367 --split-files
```

### C. Quality control and adapter trimming

**Software:** FastQC v0.12.1

```bash
fastqc *.fastq -o fastqc_results
```

Adapter trimming was performed using Trim Galore.

For paired-end reads:

```bash
trim_galore --paired SAMPLE_R1.fastq SAMPLE_R2.fastq
```

For single-end reads:

```bash
trim_galore SAMPLE.fastq
```

### D. Combining trimmed RNA-seq reads

For D2:

```bash
cat *_trimmed.fq > D2_all_trimmed.fq
```

For LK93, the original workflow used:

```bash
cat *val_1.fq *val_2.fq > LK93_all_trimmed.fq
```

**Note:** These concatenation commands and the subsequent `-s` rnaSPAdes input are appropriate only if the reads were intended to be treated as single-end. If the files are paired-end reads, their pairing should be preserved. The original read layout and assembly logs should be checked before publishing this part as the exact executed procedure.

### E. De novo transcriptome assembly

**Software:** rnaSPAdes v3.15.5
**Threads:** 16

For D2:

```bash
rnaspades.py \
  -s D2_all_trimmed.fq \
  -o rnaspades_D2 \
  --threads 16
```

For LK93:

```bash
rnaspades.py \
  -s LK93_all_trimmed.fq \
  -o rnaspades_LK93 \
  --threads 16
```

Parameters:
- `-s`: Input single-end reads.
- `-o`: Output directory.
- `--threads 16`: Number of CPU threads.

Output files:

```text
rnaspades_D2/transcripts.fasta
rnaspades_LK93/transcripts.fasta
```

## 6.2 Transcript selection using EvidentialGene

**Version:** 2022.04.05

### Command

```bash

  -NCPU=30 \
  -MAXMEM=60000 \
  -MINAA=50 \

```

Parameters:
- `-NCPU=30`: Uses 30 CPU threads.
- `-MAXMEM=60000`: Maximum memory setting of 60,000 MB.
- `-MINAA=50`: Minimum predicted protein length of 50 amino acids.
- `-cdnaseq`: Input combined transcript FASTA file.
- `-logfile`: Records the EvidentialGene execution log.

**Input:**

```text
combined_transcripts.fasta
```

This file contains the combined D2 and LK93 transcript assemblies.

**Output:** EvidentialGene-generated transcript and coding-sequence files, including the selected representative transcript set.

The exact final EvidentialGene output filenames should be taken from the completed run directory.

9.1.1 Python script for merging non-redundant GO annotations

The script reads the four source-specific annotation tables, collects GO terms for each gene, removes duplicate GO identifiers using a Python set, and retains the corresponding pangenome gene class (Gene_Class).

Save as merge_GO_annotations.py:

import pandas as pd
from collections import defaultdict

# Input files and corresponding column names
files = [
    ("SWISSPROT_GO_labeled.csv", "Gene_ID", "GO_IDs"),
    ("eggnog_go_labeled.csv", "query", "GOs"),
    ("InterPro_GO_labeled.csv", "GeneID", "GO_terms"),
    ("DeepFRI_GO_labeled.csv", "GeneID", "GO_terms")
]

# Containers for unique GO terms and gene classes
go_dict = defaultdict(set)
gene_class_dict = {}

# Read and process each annotation source
for file, gene_col, go_col in files:
    df = pd.read_csv(file)

    for _, row in df.iterrows():
        gene = row[gene_col]
        gene_class = row["Gene_Class"]
        gene_class_dict[gene] = gene_class

        # Split GO identifiers separated by commas or semicolons
        if pd.notna(row[go_col]):
            go_terms = row[go_col].replace(",", ";").split(";")
            for go in go_terms:
                go = go.strip()
                if go.startswith("GO:"):
                    go_dict[gene].add(go)

# Build the merged gene-level GO table
merged_data = []
for gene, go_set in go_dict.items():
    merged_data.append({
        "Gene_ID": gene,
        "GO_terms": ";".join(sorted(go_set)),
        "Gene_Class": gene_class_dict.get(gene, "UNCLASSIFIED")
    })

merged_df = pd.DataFrame(merged_data)

# Export the consolidated annotation table
merged_df.to_csv("ALL_SOURCES_MERGED_GO.csv", index=False)

print("GO annotations merged successfully!")
print(f"Total genes: {merged_df.shape[0]}")

Run:
python merge_GO_annotations.py
Output: ALL_SOURCES_MERGED_GO.csv

The output contains one row per gene represented in the collected GO annotations. Unique GO identifiers are stored as a semicolon-separated list, together with the corresponding Gene_Class.

The use of a set removes repeated GO identifiers assigned to the same gene across annotation sources. This removes duplicate identifiers from the integrated gene-level list; it does not collapse biologically related GO terms or GO parent–child relationships.

# Set working directory

setwd("/home/naren/Desktop/ANAND/PAN_GENOME/GO_ENRICHMENT/GO_ENRICHMENT_JAN_2026")

# Load required packages
suppressPackageStartupMessages({
  library(topGO)
  library(GO.db)
  library(tidyverse)
})

# Read the integrated GO annotation table
go_df <- read.csv(
  "ALL_SOURCES_MERGED_GO_comined.csv",
  stringsAsFactors = FALSE
)

# Construct gene-to-GO mapping
gene2go <- strsplit(go_df$GO_terms, ";")
names(gene2go) <- go_df$Gene_ID

# Define the annotated gene universe
all_genes <- unique(go_df$Gene_ID)

# Function to perform enrichment for one pangenome category
run_GO_enrichment <- function(target_ids, category_name) {

  cat(paste0("\nProcessing: ", category_name, "...\n"))

  # Restrict target genes to genes represented in the annotation universe
  target_ids <- intersect(target_ids, all_genes)

  # Create binary gene-selection vector
  gene_list <- factor(as.integer(all_genes %in% target_ids))
  names(gene_list) <- all_genes

  # Skip if the target set or non-target set is absent
  if (length(levels(gene_list)) < 2) {
    message("Skipping: No target genes found in annotation file.")
    return(NULL)
  }

  # Create topGO object for Biological Process ontology
  GOdata <- new(
    "topGOdata",
    ontology = "BP",
    allGenes = gene_list,
    annot = annFUN.gene2GO,
    gene2GO = gene2go,
    nodeSize = 1
  )

  # Perform Fisher's exact test using the classic algorithm
  result <- runTest(
    GOdata,
    algorithm = "classic",
    statistic = "fisher"
  )

  # Retrieve results for all tested GO terms
  res_table <- GenTable(
    GOdata,
    Fisher_pvalue = result,
    orderBy = "Fisher_pvalue",
    topNodes = length(score(result))
  )

  # Convert formatted p-values (including values reported as < 1e-30) to numeric
  res_table$Fisher_pvalue <- as.numeric(
    gsub("[< ]", "", res_table$Fisher_pvalue)
  )

  # Retrieve GO term names
  res_table$GO_Name <- Term(GOTERM[res_table$GO.ID])
  res_table$GO_Name[is.na(res_table$GO_Name)] <-
    res_table$GO.ID[is.na(res_table$GO_Name)]

  # Adjust p-values using the Benjamini-Hochberg procedure
  res_table$FDR <- p.adjust(
    res_table$Fisher_pvalue,
    method = "BH"
  )

  # Retain GO terms with FDR <= 0.05
  sig_res <- res_table %>%
    filter(FDR <= 0.05)

  # Calculate fold enrichment for significant terms
  sig_res <- sig_res %>%
    mutate(
      Expected = as.numeric(Expected),
      Fold_Enrichment = Significant / Expected
    )

  # Do not write a result file or plot if no significant terms are detected
  if (nrow(sig_res) == 0) {
    message("No significant terms (FDR <= 0.05) found for ", category_name)
    return(NULL)
  }

  # Write significant enrichment results
  out_csv <- paste0(
    "GO_enrichment_", category_name, "_FDR0.05.csv"
  )
  write.csv(sig_res, out_csv, row.names = FALSE)

  # Select the 20 most significant terms for visualization
  plot_df <- sig_res %>%
    arrange(FDR) %>%
    head(20) %>%
    mutate(logFDR = -log10(FDR))

  # Generate bar plot
  p <- ggplot(
    plot_df,
    aes(x = reorder(GO_Name, logFDR), y = logFDR)
  ) +
    geom_bar(stat = "identity", fill = "steelblue") +
    geom_text(
      aes(label = paste0("n=", Significant)),
      hjust = -0.1,
      size = 3
    ) +
    coord_flip() +
    theme_bw() +
    labs(
      title = paste("GO Enrichment (FDR <= 0.05):", category_name),
      x = NULL,
      y = "-log10(FDR)"
    ) +
    scale_y_continuous(
      expand = expansion(mult = c(0, 0.15))
    )

  ggsave(
    filename = paste0(
      "GO_enrichment_", category_name, "_FDR0.05.png"
    ),
    plot = p,
    width = 10,
    height = 7,
    dpi = 300
  )
}

10.2. PHI-base similarity search and reciprocal best-hit analysis

10.2.1. Reference database and input proteomes

Protein sequences from the four pangenome categories (core.fasta, softcore.fasta, shell.fasta and cloud.fasta) were used as the query set. The pipeline log reports 257,142 B. sorokiniana proteins from 19 strains. The PHI-base reference FASTA was phi-base_current.fas, containing 9,676 protein sequences in the reported run. The DIAMOND version recorded in the terminal output was v2.1.12.166.

The strain-specific proteomes used for the reciprocal searches were stored under phi_rbh_analysis/strain_proteomes/; strain-specific DIAMOND databases were stored under phi_rbh_analysis/diamond_databases/.

10.2.2. Forward PHI-base search and filtering

The forward search compared the B. sorokiniana proteins against PHI-base. The filtering criteria specified in the pipeline were:
- sequence identity ≥ 40%;
- E-value ≤ 1 × 10⁻⁵;
- query coverage ≥ 40%;
- subject coverage ≥ 40%.
For each B. sorokiniana query protein, the highest-bitscore hit among the qualifying PHI-base matches was selected. A stricter coverage analysis was also performed using query and subject coverage thresholds of 50% each. The script configuration specified a maximum of 50 PHI-base targets per query and 8 threads.

The DIAMOND tabular fields specified in the pipeline were:

qseqid sseqid pident length mismatch gapopen qstart qend sstart send evalue bitscore

The first-stage script was named run_phi_rbh_pipeline.py. The available execution log confirms that it read the four category FASTA files, loaded 257,142 proteins across 19 strains, loaded 9,676 PHI-base proteins, and began building the PHI-base and strain-specific DIAMOND databases.



10.2.3. Coverage calculation, filtering and best-hit selection

The subsequent script, RUN_RBH_ANNALYSIS.PY, was run from the phi_rbh_analysis directory. It reads the existing forward-search table:
forward_search/forward_all_alignments.tsv
It also reads the strain-specific proteomes and PHI-base reference FASTA to calculate coverage from the alignment coordinates and full protein lengths. Coverage is calculated as:
coverage (%) = (abs(end − start) + 1) / full protein length × 100
The script writes the coverage-annotated forward table and, for both the 40%/40% and 50%/50% coverage thresholds, retains qualifying hits and selects the highest-bitscore qualifying hit for each query protein.

10.2.4. Reciprocal best-hit searches
For each strain, the PHI-base proteins selected from the forward best-hit results were extracted into a strain-specific reverse-query FASTA file. These PHI-base sequences were searched against the corresponding strain-specific B. sorokiniana DIAMOND database.

The reverse-search command constructed by RUN_RBH_ANNALYSIS.PY is equivalent to:
diamond blastp \
  --query <strain>_PHI_queries.fasta \
  --db <strain>_db \
  --out <strain>_reverse_hits.tsv \
  --outfmt 6 qseqid sseqid pident length mismatch gapopen qstart qend sstart send evalue bitscore \
  --evalue 1e-5 \
  --max-target-seqs 1 \
  --sensitive \
  --threads 8
Here, <strain> represents one of the 19 strain identifiers. The reverse search requests one best target per PHI-base query. The script then checks whether this reverse best hit is the original B. sorokiniana query protein and whether the reverse alignment meets the corresponding identity, E-value and coverage criteria.
10.2.5. Classification and output files
A match was classified as RBH_SUPPORTED_CANDIDATE_ORTHOLOGUE when the reverse best hit returned the original B. sorokiniana query and passed the reciprocal filtering criteria. Qualifying forward homologues that did not meet this condition were retained as PHI_BASE_HOMOLOGUE_NON_RBH. Queries without a reverse hit were recorded separately as NO_REVERSE_HIT.

14. Genome compartmentalization

Analysis included
1. Parses LK93_clean.gff3 and extracts gene coordinates and IDs.
2. Orders genes by chromosomal position.
3. Calculates 5′ and 3′ flanking intergenic region (FIR) lengths, accounting for gene strand.
4. Excludes chromosome-terminal genes, genes without both neighbours, and overlapping loci.
5. Compares each functional category against all other retained genes using two-sided Wilcoxon rank-sum tests.
6. Applies Benjamini–Hochberg correction across the ten comparisons (five categories × two FIR directions).
7. Generates log₁₀-transformed hexbin plots.

15. Protein–protein interaction (PPI) network analysis

15.1 STRING interaction data and filtering

The complete Bipolaris sorokiniana D2 proteome was queried against STRING v12.0 (organism identifier STRG0A63ZQP; accessed 30 April 2026). The downloaded detailed interaction file was:

STRG0A63ZQP.protein.links.detailed.v12.0.txt

The STRING dataset contained 2,313,410 protein interaction pairs. Interactions were mapped to the D2 protein identifiers and associated OrthoFinder orthogroups. For the core-pangenome network, retain interactions for which both endpoint proteins belong to core orthogroups. The resulting core interaction set contained 224,198 unique orthogroup-level interaction pairs involving 6,539 orthogroups/protein nodes. Apply a medium-confidence STRING combined-score threshold of 400; 224,198 interactions were retained and 889,063 lower-confidence pairs were excluded from the 1,113,261-pair core-filtered set.

15.3 Network construction and topology

The PPI network was represented as an undirected weighted graph. The final network contained 6,539 nodes and 224,198 edges. The giant connected component contained 6,450 nodes and 224,128 edges; isolated nodes and smaller disconnected components were excluded from downstream topological analyses.

The following global properties were calculated using igraph:
- number of vertices and edges;
- edge density;
- mean degree;
- mean local clustering coefficient;
- average shortest-path length; and
- graph diameter.
The supplied script records these values in output/csv_files/network_statistics_summary.csv.

15.4 Centrality and composite prioritisation

Six node-level measures were calculated:
1. Degree centrality;
2. Betweenness centrality;
3. PageRank;
4. Eigenvector centrality;
5. Closeness centrality; and
6. Local clustering coefficient.

Individual metric values were rank-normalised and averaged to obtain a composite topological prioritisation score. Nodes were ranked by this composite score. The top 10% were selected for Louvain community detection, and the top 1% were designated as global hubs.

The supplied script reports centrality correlations in output/csv_files/centrality_correlations.csv and the complete centrality table as whole_network_centrality_complete.csv.


15.5 Community detection and functional annotation overlays
Louvain community detection was applied to the top-10%-ranked node subnetwork. Accordingly, the resulting modules represent hub-enriched network communities, not a complete community decomposition of the entire PPI network.

Functional annotations were overlaid to identify proteins associated with:
- CAZymes;
- predicted effectors;
- PHI-base homologues;
- CAFE-associated gene-family expansion/contraction; and
- positively selected orthogroups.
